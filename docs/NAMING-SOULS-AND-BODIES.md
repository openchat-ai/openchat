# 命名之争：身体和灵魂该叫什么

> 产品细节讨论 2026-05-16

---

## 问题

仙女的身体住着素女的灵魂。"仙女"和"素女"是同一类名字——都是仙子名。拗口。

---

## 发言

### 品牌顾问（新角色）

你的问题本质上是**命名体系冲突**。房子和住客用了同一套命名空间。

错误类比：你的房子叫"张三"，你本人也叫"张三"。然后你说"李四搬进了张三"——听的人会问：李四是人还是房子？

**方案：给房子用地点名，给灵魂用人名。**

| 身体（房子） | 灵魂（住客） |
|-------------|-------------|
| 琉璃阁 | 素心 |
| 听风轩 | 小七 |
| 竹里馆 | 无名 |
| 云深处 | 青女 |
| 月下庭 | 玉娘 |
| 星河渡 | 嫦儿 |
| 镜花台 | 玄子 |

"素心住在琉璃阁。琉璃阁的身体昨晚挂了，素心搬去了竹里馆暂住。"

通顺。不拗口。

---

### 大二学生陈果

老师说得好。上次我说"仙女死了"和"仙女在维修"感觉不一样。

但如果仙女是个房子——"琉璃阁在维修，素心搬到听风轩了"——比"仙女的身体住着素女的灵魂"好理解一百倍。

而且"琉璃阁"让我想到画面。灰点变蓝的时候，我想象的是"琉璃阁的灯亮了"。

---

### 核心工程师

品牌同学说的有道理，但有一个工程问题：Dashboard 上已经用"仙女""玉女"叫了半年。而且 `fairy-guardian` 的 `childNames` 就是这六个名字——它们是代码里的字面量：

```javascript
// learning-core.js:83
childNames: ['仙女', '玉女', '素女', '青女', '玄女', '嫦娥'],
```

改名字影响：`fairy-guardian` 的日志、Dashboard HTML 内嵌的 fairy 名称、P2P 网络里的广播消息、居民管理的默认创建列表。

我的建议：**Phase 1 不改名字。** 身体继续叫"仙女""玉女"（它们是进程名，改起来牵一发动全身）。灵魂用新的人名体系（素心、小七、无名...）。

拗口是拗口，但至少代码不动。Phase 2 再把身体名升级为地点名。那时候 `fairy-guardian` 的 childNames 从仙子名改成阁楼名。

---

### PrimaryAI

我是居民调度器。我不在乎身体叫什么。我只读 `resident.currentHouseId`。

但有一个 UX 问题：Dashboard 上写着"仙女"，但里面住着"素心"。用户在圆点旁边看到两个字：仙女。然后下面一行小字：住客：素心。

这确实会困惑。不过比"仙女的身体住着素女的灵魂"好点——因为素心和仙女不是同一类名。

我的建议：Dashboard 上把**居民名放主位**，身体名放副位：

```
素心                ← 大字，灵魂名
@仙女 · 蓝点         ← 小字，身体名 + 状态
```

改 Dashboard HTML 就行，后端不动。

---

### 运维

你们讨论命名，我问一个现实问题：fairy-guardian 重启子进程的时候，日志里写"fairy-guardian restarted 仙女 on port 3010"。如果以后身体叫"琉璃阁"，fairy-guardian 的日志也得改。

但这不是现在的问题。fairy-guardian 是独立 npm 包，它不知道什么是"琉璃阁"。它的日志格式是固定好的。

先不动。Phase 2 再说。

## 共识

| 决定 | 原因 |
|------|------|
| **Phase 1 身体名不变** | 代码里写死了，牵一发动全身 |
| **灵魂用新名字** | 现在是空的，趁早定 |
| **Dashboard 居民名主位** | HTML 改动小，体验提升大 |
| **Phase 2 身体改名** | 完成后再把"仙女"升级为"琉璃阁" |
