# spec: 43.mjs — dna-agent-loop
> DNA 符号检索 + hashline 锚点编辑接成自主闭环，对标 Cursor agent（确定性路线）

## 数据流
```
目标(改某 export 一行)
  → dna_query("find function X")   → {file, line, hash}   [C1]
  → read_file(file)                → 读上下文（可选）
  → hash_edit(file, hash, newLine) → 命中改行            [C2 成功 / C3 HASH_STALE]
  → 若 HASH_STALE → dna_query 刷新 hash → 重试            [C3→C1 自修]
  → 校验文件内容含新行                                    [C4]
```
本实验自建轻量 agent 循环（脚本化 mock LLM 产生 tool calls），驱动上述数据流，
不依赖真实 provider，test() 确定性可回归。所有编辑作用于临时文件，绝不改真实源码。

## 接口签名
- `runLoop({ goal, tools, mockPlan }): Promise<{ ok, rounds, trace }>` — 逐 round 执行 mock LLM 计划的 tool call，经 executeTool 分发
- `run({ inputs }): Promise<{ outputs }>` — compose 契约入口
- `test(): Promise<{ ok, info }>` — closed-loop 断言
- 复用（不新写）：coding-lib `executeTool` / `hashEdit` / `readFile`，42 `answerFromDNA`

### coding-lib.mjs 改动（工具接入，E43 核心）
- `TOOLS` += `dna_query` / `read_file` / `grep` / `hash_edit` 四个 schema（复活退化的 tool-loop 工具集）
- `executeTool` switch += 对应 case：
  - `dna_query({query})` → `answerFromDNA(query).answer`
  - `read_file({path})` → `readFile(path)`
  - `grep({query})` → `grepSearch(query, args)`
  - `hash_edit({path,hash,newContent})` → `hashEdit(...)`，命中抛错转 `{ok:false, code:'HASH_STALE', hint, path, hash}`

## 边界条件
- hash 失配：executeTool('hash_edit') 返回 HASH_STALE 结构化（不抛），供 LLM 自修；
  直接调 `hashEdit()` 仍抛错（保持 09 现有测试 1568 语义）
- dna_query 未命中：answerFromDNA 返回 "... not found"，循环记为无进展，不崩
- 临时文件路径必须在 PROJECT_ROOT 内（hashEdit 已做 path traversal 防护）
- 循环有 maxRounds 上限，超出即终止（防死循环）
- 空 mockPlan → 返回 ok:false，不抛
